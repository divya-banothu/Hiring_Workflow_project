# Before you submit

1. Read the challenge statement and data dictionary.
2. Run the starter generator and tests on your own machine.
3. Run the full profile and inspect row counts, labelled exceptions, and validation results.
4. Review the code and make any improvements you can explain in your own words.
5. Do not claim the prototype is production-ready or that it integrates with live HR systems; it is a synthetic workflow/data-quality implementation.
6. Push source, tests, documentation, and schema to a public GitHub repository. Do not commit `.venv` or large generated output files unless the client explicitly asks for them.
